## Запуск и Настройка

### 1. Запуск контейнеров

```bash
docker compose up -d --build
```
*Примечание: Приложение `pymongo_api` может перезагружаться первые пару минут, пока кластер не будет готов. Это нормально.*

### 2. Инициализация кластера

Необходимо дать права на выполнение:
```bash
chmod +x ./scripts/init-cluster.sh ./scripts/load-data.sh
```

Запустите скрипт, который объединит ноды в реплика-сеты и зарегистрирует шарды в роутере:

```bash
./scripts/init-cluster.sh
```

После инициализации перезапустите контейнер API, чтобы он успешно подключился к настроенному кластеру (если он упал):
```bash
docker compose restart pymongo_api
```

### 3. Заливка данных и шардирование коллекции

Чтобы увидеть шардирование в действии, мы должны явно указать правило (Shard Key) для коллекции `helloDoc` базы `somedb`. Запустите:

```bash
./scripts/load-data.sh
```

В конце вывода вы увидите статистику `Shard Distribution`. Примерно 50% данных должно быть на `shard1RS` и 50% на `shard2RS`.

## Проверка работы

### Через API Приложения

Откройте в браузере:

1.  **Статус кластера:**
    [http://localhost:8080/](http://localhost:8080/)
    *   Ищите поле `"mongo_topology_type": "Sharded"`.
    *   В поле `"shards"` должно быть 2 записи.

2.  **Количество документов:**
    [http://localhost:8080/helloDoc/count](http://localhost:8080/helloDoc/count)
    *   Должно вернуть `items_count: 1000`.

### Ручная проверка (в терминале)

Вы можете проверить, что данные физически разделились между серверами:

```bash
# Смотрим данные на Шарде 1
docker compose exec shard1 mongosh somedb --eval 'db.helloDoc.countDocuments()'

# Смотрим данные на Шарде 2
docker compose exec shard2 mongosh somedb --eval 'db.helloDoc.countDocuments()'
```
Сумма этих чисел должна давать 1000, но на каждом отдельном шарде будет только часть данных (например, ~500).

## Полезные команды

Если нужно пересоздать всё с нуля:

```bash
# Остановить и удалить контейнеры и тома (данные сотрутся)
docker compose down -v

# Запустить заново
docker compose up -d
```
